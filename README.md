# Сервис обмена одеждой «Круговорот вещей»

## Описание проекта

«Круговорот вещей» — веб-приложение для обмена одеждой, позволяющее пользователям находить новые вещи и продлевать срок их использования. Сервис предоставляет каталог доступных вещей, поиск по названию и просмотр статистики по владельцам.

Проект разрабатывается в рамках дисциплины «Технологии разработки приложений на базе фреймворков» и является сквозным индивидуальным проектом.

## Используемые технологии

- Python 3.14
- Django 6.1
- SQLite
- Django ORM
- HTML, CSS, JavaScript
- JSON
- pytest
- flake8

## Модели данных

Начиная с практической работы №9, для описания структуры базы данных используется Django ORM. В приложении `items` реализованы три модели.

### User — пользователь

- `id` — первичный ключ;
- `name` — имя пользователя;
- `email` — адрес электронной почты (уникальный).

### Item — вещь

- `id` — первичный ключ;
- `owner` — владелец вещи (связь с моделью User);
- `item_name` — название вещи;
- `size` — размер;
- `condition` — состояние вещи;
- `is_available` — доступность для обмена.

### ExchangeRequest — заявка на обмен

- `id` — первичный ключ;
- `item` — вещь, на которую подана заявка;
- `requester` — пользователь, подавший заявку;
- `status` — статус заявки (`active`, `cancelled`, `completed`).

## Реализованные страницы

- **Главная страница (`/`)** — каталог доступных для обмена вещей, отсортированный по названию.
- **Карточка вещи (`/items/<id>/`)** — подробная информация о выбранной вещи и похожие предложения того же размера.
- **Поиск (`/search/`)** — поиск вещей по названию без учёта регистра.
- **Статистика (`/statistics/`)** — отображение количества вещей у каждого владельца.

## Работа с базой данных

В ходе разработки проекта было реализовано два этапа работы с базой данных.

### Практическая работа №7 — SQLite

На данном этапе использовалась база данных SQLite. Доступ к данным осуществлялся с помощью библиотеки `sqlite3` и SQL-запросов.

Файлы `sql/schema.sql`, `sql/queries.sql` и `db/database.py` сохранены в проекте для демонстрации предыдущей реализации.

### Практическая работа №9 — Django ORM

На следующем этапе проект был переведён на Django ORM. Структура базы данных теперь определяется моделями Django, а изменения применяются с помощью миграций.

Для получения и обработки данных используются ORM-запросы. Также был подготовлен скрипт `db/import_sqlite_to_orm.py` для переноса данных из предыдущей базы SQLite.

### Примеры ORM-запросов

Получение доступных вещей:

```python
Item.objects.filter(is_available=True).order_by('item_name')
```

Поиск по названию:

```python
Item.objects.filter(
    item_name__icontains=query,
    is_available=True
)
```

Подсчёт количества вещей у каждого владельца:

```python
Item.objects.values('owner__name').annotate(
    items_count=Count('id')
).order_by('-items_count')
```

## Установка и запуск проекта

1. Клонировать репозиторий:

```powershell
git clone <адрес репозитория>
cd clothing-exchange
```

2. Создать виртуальное окружение:

```powershell
python -m venv .venv
```

3. Активировать виртуальное окружение:

```powershell
.venv\Scripts\activate
```

4. Установить зависимости:

```powershell
pip install -r requirements.txt
```

5. Применить миграции:

```powershell
python manage.py migrate
```

6. При необходимости перенести данные из базы предыдущей практической работы:

```powershell
python db/import_sqlite_to_orm.py
```

7. Запустить сервер:

```powershell
python manage.py runserver
```

8. Открыть в браузере:

```text
http://127.0.0.1:8000/
```
